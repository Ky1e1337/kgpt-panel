# 降本增效分工规则

> 成本现实：主模型 **deepseek-v4-pro 按量计费（贵）**，KGPT 子 agent **免费**。
> 目标：付费模型只做"判断"，免费子 agent 干"脏活累活"。

## 一、分工铁律

### 丢给免费子 agent（KGPT）的活
- 读文件 / 列目录 / 找代码
- **PDF 文本提取**（子 agent 自己用 bash 的 `pdftotext`，主 agent 不替它干）
- 逐条核对 / 搜索 / 格式转换
- 批量脚本 / 跑测试 / lint
- 写初稿报告 / 样板代码

### 只留给付费主模型的活（高价值判断）
- 理解用户真实需求与约束
- 定方案、定验收标准
- 派发子 agent
- **交叉对比多个子 agent 的结果 + 最终裁决**
- 给用户看的总结

## 二、派发方式

通过 KGPT Panel 调度（面板需在用户终端 `python3 app.py` 运行，浏览器 `http://127.0.0.1:8787` 看过程）：

```bash
curl -X POST http://127.0.0.1:8787/api/run \
  -H 'Content-Type: application/json' \
  -d '{"provider":"KGPT","prompt":"<任务>"}'
```

- 查询结果：`curl -s http://127.0.0.1:8787/api/tasks`
- 能并行就并行派 2-4 个子 agent 独立做或交叉检查，父只做合并与仲裁

## 三、注意事项

1. **子 agent 读 PDF 返回二进制**（不会自动提文字）——让子 agent 自己 `pdftotext`，别在主模型这边预提取。
2. **本地沙箱连 127.0.0.1 被禁网**时，加 `sandbox_permissions=danger-full-access` 提权。
3. **不为派而派**：小改动、单文件、简单问题直接自己干（派发本身也耗 token）。
4. **子 agent 是自报**：重要结论主模型要复核，不照单全收。
5. **交叉检查优先**：重要/易错的任务，派两个独立子 agent 从不同角度核查，父做一致性比对，分歧处仲裁。
